## Info

- **SR-2 and the source confirmation.** The `source_confirmation` item carries up to 200 quotes of up to 1,000 characters each, and the skill shows them through Claude. So Claude in the skill does read document text, despite SR-2's "never reads, shows or summarizes the document". The contract designed it that way (H-0105). The client fences the quotes and strips invisible characters. The owner may want SR-2's wording to name this exception.
- **Secret refusal without a Security item** (dev report interpretation 3). It fits SR-11: the refusal names lines and the rule only, never the value, and nothing was stored or sent to a model. Acceptable.
- **gitleaks line numbers.** gitleaks counts lines by LF; the engine's own refusals split on CR, LF and CRLF. In a CR-only document a secret's line number won't match the other refusals. Display only.
- **Decoy files.** The deny globs cover `F-nnn-source.md` and `.txt` only, so the analyst may write `docs/features/F-nnn-source.md.md` or `F-nnn-source.markdown`. The engine always reads the stored blob, so this could only confuse a human reader.
- **Windows names.** A short 8.3 name such as `X~1.TXT` can stand for `x.txtx` and pass the extension check; the engine validates the text anyway. The device-name pattern misses `COM¹` to `COM³` and `LPT¹` to `LPT³`, and the `S_ISREG` check catches those. Trailing dots and spaces are refused by the extension check (`doc.md.` gives the extension `.`).
- **Reparse points.** The client refuses every reparse point, which also refuses OneDrive "Files On-Demand" placeholders. A usability cost, not a security one.
- **Failed starts.** If `update-ref` fails after `storeDocument`, an unreferenced blob and commit stay in the local object store. They are never pushed.
- **SR-13 deferred.** The contract lists `budget` as a refusal reason; the engine never sends it. This is the owner's deferral to Alpha and is already a known issue.

## Checked and fine

- **-32009 data path.** Every `DocumentRefused` message is fixed text. `data` carries a reason from the list, at most 50 positive line numbers, and a rule id that already matched `^[A-Za-z0-9_.-]{1,100}$` in `gitleaks.ts`. The client's `_refusal` drops anything off that shape, and `error_display` shows its own sentence instead of the engine's message for -32009. gitleaks runs with `--redact`.
- **Document text never reaches stdout, errors or logs.** `cmd_start` returns name, size and provenance only. Every `read_document` error is fixed text, `UnicodeDecodeError` is suppressed, and an unexpected exception gives a fixed message with no traceback. The engine logs only the feature id. The transcript keeps name, type, provenance, path, size, SHA-256 and blob id, never the text.
- **`document.name`.** Control, line-separator and invisible characters are stripped, it is limited to 200 characters, and it appears only in the transcript and the client's cleaned output. It is never in a path, commit message, git argument or prompt (SR-10).
- **Git plumbing.** `hash-object -w --no-filters` with a read-back compare, a private index file in the owner's temp folder, `read-tree`, `update-index --cacheinfo` at the engine's own path, `commit-tree` with a fixed message, and `update-ref` with a zero old value, all under the engine's git overrides (no hooks, fsmonitor, filters or system and global config). The project's checkout and index are never touched.
- **Integrity of the stored document.** Read back by blob id and refused unless its SHA-256 matches the transcript, before the first turn and before every quote check. A mismatch fails closed (`SessionRefused`, `unavailable`).
- **Engine-side validation (SR-9).** Unknown keys, types, `media_type`, `provenance`, lone surrogates, size in UTF-8 bytes, and C0, DEL and C1 controls, all before the start lock, so a refusal creates nothing. The secrets scan runs before an id is assigned (AC-3).
- **Client read (SR-4, SR-6 apart from H2 and L2).** `lstat`, then `O_RDONLY | O_NOFOLLOW | O_NONBLOCK`, then `fstat` comparing device and inode with the `lstat`, a regular-file check, and at most limit + 1 bytes read. On POSIX this closes the swap window and the FIFO hang. The file is read before connecting, so a refused document sends nothing.
- **Role policy v2.6 (SR-5).** `checkRole` requires both source denies for every role that writes outside `.factory/`. The onboarding template and `factory_check.py` carry them. A source file can never be a `spec_path`.
