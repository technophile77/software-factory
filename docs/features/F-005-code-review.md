## Info

- **`data.started_at` on `busy` (SR-16 exception).** The client reads only `error.data.started_at`, only for code -32001, and only when it fully matches a strict ISO 8601 pattern. It drops `data` otherwise (`interview_client.py:469-476`). That carries nothing but a timestamp, so it is safe, but it departs from the letter of SR-16 and the contract ("clients don't show `data`"). H-0025 says `busy` comes "with `started_at`" but not where. The owner should settle that in the contract: `data.started_at`, or a field in `message`.
- **macOS peer check.** `LOCAL_PEERCRED` at `SOL_LOCAL` 0, option 1, with a 76-byte `struct xucred` (version, then uid) matches the macOS headers. A wrong layout or an `OSError` gives a uid mismatch or `None`, and both refuse, so an error fails closed. It is untested, so the cost of a mistake is availability, not a bypass.
- **`git` environment.** `run_git` keeps the caller's `GIT_DIR`, `GIT_WORK_TREE` and `GIT_CONFIG_*`. These come from the owner's environment, not the repo, as noted in F-003 R4. A folder that wasn't cloned (an extracted archive with its own `.git`) controls the worktree registry, so the worktree check can be satisfied there. The socket owner, folder mode and peer uid checks still confine the result to the owner's own sockets.
- **Picker labels.** AskUserQuestion labels are meant to be short. A long option copied "character for character" (`SKILL.md:135-138`) may tempt the model to shorten the label. The rule that the reply text is the option text, not the label, would help.
- **Engine pid.** `engine.json`'s `pid` is validated but never compared with the peer pid from `SO_PEERCRED`. Comparing them would be a cheap guard rail. Under SR-5 it is not a boundary.

## Checked and fine

- **Command line (SR-9, S1.3):** the only argument is a fixed subcommand name. Requests go on stdin through a quoted heredoc (`<<'SF_REQUEST_END'`), so there is no expansion. The only engine text that can reach a request is a picked option, which `clean(single_line=True)` has already stripped of `\n`, `\r`, U+2028/9 and NEL, so it can't produce the end-marker line. Ids, session tokens and revisions are checked by pattern or type before connecting, and so is every id that comes back from the engine. Unknown fields are refused. `git` runs with a fixed argument list, no shell, `core.fsmonitor=false`, `core.hooksPath=/dev/null` and a timeout. `python3 -I` prevents planted modules.
- **`engine.json` location (FR-2, SR-1):** the script trusts only `<main worktree>/.factory`. That path must not be a symbolic link and must resolve to a `refs/heads/factory/state` worktree listed by `git worktree list --porcelain -z`. A tracked `.factory`, a plain folder, another branch, a link, a linked `engine.json`, a non-regular or oversized file, a file owned by another user and a committed `engine.json` are all refused (tested, and checked by reading the code). The version, pid and path format follow H-0025.
- **Socket (SR-1, SR-8):** abstract (`\0`, `@`) and relative addresses are refused. The socket must not be a link, must be a socket, and must be owned by the euid. Its resolved folder must be owned by the euid with no group or other bits. The path checks can race, but the `SO_PEERCRED` uid is read after connect and before anything is sent, and that check can't be raced. A uid that can't be read refuses.
- **Framing and limits (SR-15):** one message per line. The buffer is capped at about 1 MiB plus one 64 KiB read. A deep-nesting `RecursionError` and invalid UTF-8 fail closed. Each call has an absolute deadline of 60 s plus `wait_s`, so slow-drip bytes and endless notifications are bounded. `wait_s` is capped at 600. Responses are matched by id, and notifications are skipped.
- **Display (SR-2, SR-10):** every engine field is fenced with a fence longer than any backtick run inside it. Labels, ids, revisions and statuses come from the script or are validated. CSI and OSC sequences, C0/C1 controls, bidi controls, zero-width characters, tag characters, the BOM and line separators are removed (tested, and reproduced). The exceptions are in #1 and #3.
- **Errors (SR-16):** `data` is dropped apart from the narrow `started_at` case. A stdin decode error uses a fixed message, so it never quotes the owner's text. A failure after a reply carries `reply_id` and `reply_sent`.
- **Retries (FR-13, SR-12):** `reply_id` is a client-side uuid4. A retry calls `interview.state` first and resends only if the revision and status are unchanged; the engine de-duplicates by `reply_id` in any case. Nothing retries on its own. A failure while waiting after a recorded reply is reported as `wait_failed`, not as a reply to resend.
- **Relay rules (SR-3, SR-10, SR-13):** SKILL.md forbids answering, picking, approving, rewriting and unrequested `more_info` or `defer`. Every reply comes from the owner's picker choice or typed text in that turn, with fixed texts for "Defer" and the assumption labels. The `suggested` answer is never offered as a one-click choice. An option number typed on its own is confirmed with the owner. `takeover` is sent only after the owner's yes. A `stale` item is re-shown, never re-sent. Tools are limited to the script and the picker by instruction. Claude Code's `allowed-tools` grants tools but can't restrict them, so the instruction is the only control available. Leaving the Bash prompts in place keeps the owner seeing every command.
- **No local record (SR-4, FR-10):** the script opens no file for writing and logs nothing. SKILL.md warns the owner about secrets and about Claude Code's own history.
- **Role policy v2.2 checker:** `"*"` is refused for any role with a file tool, `Skill` included, whether set in the project policy or through a repo override (repo overrides go through the effective policy, and tool widening by an override is refused). Tool names are matched exactly, so `read` and ` Read` are refused as unknown. Role names and policy keys are matched exactly, and the YAML reader refuses duplicate keys. Duplicate repo names are refused. `.factory/engine.json` and `**/.factory/engine.json` are required in every role's read deny list, and the template's six roles, `web-reader` included, have them. The template's `web-reader` has exactly the contract's fixed policy. Gaps: #2 and #10.
- **README, `plugin.json`, `marketplace.json`:** text and version changes only. They add no install hook or command.

### Info

- **Host names (#2).** The new check accepts IP literals and single labels: `localhost`, `127.0.0.1`, `0.0.0.0`, the cloud metadata address `169.254.169.254`, and a bare `com`. These are explicit grants in a change-controlled manifest, not wildcards, so this is not a finding. Refusing IP literals and single-label names would close the obvious SSRF targets for a role that has file tools.
- **Timeout wording.** When the run limit cuts a call short, the message still says "within 60 seconds". Reproduced with a 20 s limit and a silent engine: the call stopped at 20.0 s and the message said "60 seconds". Saying "in time" would be accurate.
- **Pid match (Code Review Info, now done).** On Linux, `SO_PEERCRED`'s pid must equal `engine.json`'s `pid`. An unreadable pid refuses, so it fails closed, and a mismatch is refused (reproduced: `peer_not_engine`). The engine must therefore write the pid of the process that calls `listen()`. The contract should say so, or an engine with a launcher or wrapper process will be refused.
