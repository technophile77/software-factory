## Info

- **`allow_loopback`.** The engine pins `127.0.0.1` for a loopback endpoint, but the proxy that connects to it runs in the sidecar container, where loopback is the sidecar itself. Such an endpoint passes the start check (run on the host) and then fails every session. It fails closed; the spec or ADR should say loopback needs `host.docker.internal` or isn't supported.
- **Private HTTPS endpoints.** The router's CONNECT is allowed only to public endpoints, and the plain-HTTP forward only to `http` ones, so a private endpoint on `https` can't be reached. Fails closed; worth stating in the endpoints file contract.
- **Advisory wording.** `advisoryBlock` calls the hints "from a local model" whatever the endpoint is. Cosmetic.
- **Advisory text filter.** `clean` refuses C0 controls and bidi overrides but not zero-width or other invisible characters. Low risk: the hints are JSON inside a fence the data can't close, and they are labelled unverified.
- **Subscription reserve and concurrency.** The plan check runs when a session starts and the use is counted when it ends, so with `max_sessions` above 1 parallel sessions can together pass `100 - reserve_pct`. The reserve absorbs it for small plans.
- **Probe on OpenAI-format endpoints.** `/v1/models` is appended to the base path, so a base URL ending in `/v1` is probed at `/v1/v1/models`. Functional, not security.
- **`withoutHost`.** Replaces the host by plain substring; a one-letter host would garble the message. Cosmetic.

## Checked and fine

- **Endpoint grants (FR-5, AC-4).** The grant, not the agent, names the upstream; `startAgent` refuses an upstream the run's router doesn't serve; the gateway rewrites `model` to the granted endpoint's name. Requests to the router are built from nothing: master key, content type and length, `anthropic-version`, `accept` and allow-listed betas only; the agent's headers (dummy key) and the Claude credential never go to the router. An agent credential presenting its own key is still refused.
- **Router egress.** A router grant can't use the gateway. CONNECT only to a public, `https` pinned endpoint matched on host and port, dialled at the pinned address with no DNS. Plain HTTP only to a private, `http` pinned endpoint, at its pinned address, without userinfo, GET or POST only, re-checking the grant after the body is read. Agent grants can use neither path (AC-5 test). `setEndpoints` refuses a pin whose address contradicts its class, and `main.ts` refuses a router address off the internal subnet.
- **One key per router.** Each endpoint session gets its own group and router holding only that endpoint and its pin (`endpoint-service.ts:279`), so a key can't be sent to another endpoint through this design (SR-13).
- **Body allow list and fold (SR-17 condition 4, FR-16).** Top-level allow list, only `metadata.user_id`, dropped names logged without values; the fold rebuilds plain text blocks and logs only counts; Anthropic-bound requests unchanged. Covered by stochastic tests. The query is limited to `?beta=true` and no LiteLLM-specific header reaches the router.
- **Redirects and caps (SR-13, SR-16).** Any 3xx from the router or a private endpoint becomes 502 and is never followed; a declared or streamed body over the cap is cut by closing the connection. The probe uses Node's `http.request`, which follows nothing; its tests cover a 302.
- **Address classification (FR-4, SR-3, SR-15).** Every answer is classified; any refused-class answer or a mix of private and public fails; IPv4-mapped addresses take the inner address's class; NAT64, 6to4, Teredo, CGNAT, documentation and multicast are refused; the first answer is pinned and re-resolved before each session; public endpoints need `https`, a key and non-`local` billing. A stochastic test compares the classifier with a reference.
- **Probe (FR-6).** Connects to the pinned address, keeps the URL's host for the Host header and TLS name, checks certificates with TLS 1.2 or later, sends the key only in the endpoint's own auth header, sends a fixed generic prompt ("Call the tool.") and nothing from any project, caps the reply at 1 MiB, and reports reasons without addresses.
- **Endpoints file (FR-2, AC-2).** Refused when a link, not a regular file, over 64 KiB, not owned by the user or group/world-writable (POSIX), or not owner-writable-only by SDDL (Windows); unique keys, no aliases; error messages never repeat a value. The key reference can name only `endpoint-key/<name>`.
- **Container hardening (SR-16).** Pinned image by id with its digest checked, numeric non-root user, read-only root, all capabilities dropped, no new privileges, CPU, memory and pids limits, size-capped tmpfs only at `/tmp` and `/app/.cache` (checked by `inspectMismatches`), no log driver, telemetry, cost-map download, admin UI and docs off, no database configured, per-run random master key, config file with key references only.
- **Advisory pass (SR-10, FR-10, FR-11).** Criterion and severity must match the standards given; location and description are trimmed, capped and refused on control or bidi characters; at most 50 findings; the verdict is one of three words; the block is JSON with `<` and `>` escaped inside a fence it can't close, labelled unverified; it passes the gitleaks scan before Claude sees it; the gate result comes only from the Claude report; every failure path skips the hints and the gate continues.
- **SR-9.** `reviewerPolicy` refuses commands and network hosts for the security reviewer, so the only endpoint session today is read-only with no network; `planRole` refuses a role that writes outside `.factory/` or has network hosts; gate roles can only take `advisory`.
