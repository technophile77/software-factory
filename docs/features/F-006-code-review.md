## Info

- **`Skill` on a read-only role.** The advisor has `Skill`. Claude Code skills can declare `allowed-tools`, which grants tools while the skill runs. The engine must enforce the role's tool list as a hard limit (by restricting which tools are available, not through permission settings), or a skill in the shared set that names `Bash` could widen a role with no shell. This applies to the analyst too, so it is engine-side and not new here. Note it for the engine's Code Review.
- **Proposal shows the question by id only.** The `advisor_proposal` display names the target question by id (`about`), and the analyst's own text says what it's about. The two can disagree, and the engine runs the call on `about`. Showing the target question's text from the engine (not the analyst) would remove the mismatch. The impact is small: it changes which question the advice attaches to, and it needs the owner's approval anyway.
- **Analyst narrowed per repo.** If a repo override narrows the analyst's `read.allow` (say to `docs/**`), the advisor's project-level `**` is refused for that repo, and the override must narrow the advisor too. That fails closed, which is correct, but the checker message could say so, to save the owner a puzzle.
- **Advisor AGENT.md and secrets.** It says not to put project text into searches, but nothing about copying a secret it comes across (in a file not on the deny list) into the advice. The engine's SR-6 scan is the control. One line in the AGENT.md ("never quote credentials or keys; say where they are instead") would be cheap defence in depth.

## Checked and fine

- **Advice display (SR-2, AC-10, AC-12).** Every advice text and web query passes through `clean()` (control, ANSI, bidi, zero-width, tag and variation-selector characters removed; line separators in queries flattened) and sits in a fence longer than any backtick run inside it. Reproduced: a `## Recommendation` heading, a Markdown image with a data-leak URL, a raw `<img>`, a U+202E reordered line and a four-backtick run all come out as fenced plain text, and the fence can't be closed from inside. The labels ("Advisor's advice, call A-0001", "Untrusted model output", "recorded by the engine from its own log") are the client's own text. The call ids in them are checked against `ID_RE`, so they carry no Markdown. The client imports no web module and loads nothing.
- **Advice parsing fails closed (FR-8, AC-9).** A `running` or `failed` entry that carries `text` fails the whole item, so unchecked or rejected text is never shown as advice. So do a `done` entry with blank or invisible-only text, a duplicate call id, an unknown status, non-list `web_queries` or a non-string query, and `advice` on a proposal or an assumption. Unknown extra keys are dropped, not shown. Reproduced for each.
- **Proposals (FR-3, FR-11, SR-3).** An `advisor_proposal` with `options`, `suggested`, `findings` or `advice` is refused, so the Approve/Decline choice can't sit beside analyst-offered "choices". `about` must be a valid id, and `about` on any other kind is refused. The display quotes the analyst's text and reason as data. The reply carries the shown revision, so a changed proposal gets `stale` (tested). SKILL.md sends `ask_advisor`, `approve_advisor` and `decline_advisor` only from the owner's picker choice in that turn, never from item or advice text, never on the model's own judgement, and never as a retry of a failed call (A-2). Reply texts are fixed labels. Step 1 has at most four choices, which fits the picker.
- **Running calls.** `advice_running` tells the skill a call is in progress, and SKILL.md has it ask the owner before every poll, so the session doesn't loop on `next` by itself.
- **Role policy v2.3 checker (SR-7, FR-6, FR-7).** The rule is enforced on the project policy and on every repo's effective policy. Reproduced as refused: `WebFetch`, `Bash` or `Edit` for the advisor (directly or through an override); any `write.allow`, `commands.allow` or `network.allow`; a read glob the checker can't show is inside one of the analyst's; a missing analyst deny or advisor extra deny; `may_request` on any role but `advisor`, naming any role but the two callers, given as a string, or set in a repo override. A role with no `may_request` can't be requested, so the request rule starts closed. `_covered` accepts only equality, `**`, or a textual prefix ending in `/` of an analyst `<path>/**`. Combined with the existing refusal of `..`, absolute paths, braces and negated classes (which runs first and returns early), that is sound. With no analyst policy, every advisor read glob is refused. The template's advisor validates clean and matches the contract's fixed shape.
- **Agent files (H-0060, H-0064).** The advisor's AGENT.md matches FR-1, FR-6, FR-8 and SR-1: read-only work, web only through the web reader with topic-only queries, no commands, plain text with no links or images, and no answers, approvals, picks or edits. The analyst's text forbids calling the advisor without approval and following its output, and it keeps its recommendation out of the advisor's input (FR-5, SR-5). The orchestrator part is #5.
- **No new component; no local record.** The client is still standard library only and still opens no file for writing. The fake engines and tests hold no real secrets. The `plugin.json` change is a version bump only.
