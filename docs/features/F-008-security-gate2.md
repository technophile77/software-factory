## Info

- **SR-7 layout of the spec.** The transcript and additions are in labelled blocks as JSON strings. The spec isn't quoted: the reviewer reads it with `Read`, and the engine's instruction labels it as data. This meets SR-2. It is a looser reading of SR-7's "each untrusted text … in a labelled data block". Quoting the spec as a JSON string too would close it, at some cost in tokens.
- **SR-7 checks are weak by design.** Any `SR-n` row with text counts as "section 9 has a requirement", whatever its status (a `Rejected` row counts). `CITES_SPEC` accepts any `A-1` or "section 2". The spec accepts this residual risk (Gate 1 #1); Gate 2 and validation review independently.
- **Report folder contents.** The engine reads only the named file and wipes the folder before and after the run, but it doesn't refuse a run whose folder holds other entries. Only the gated `Write` can reach it today, so this is defence in depth for AC-13.
- **Blob size.** `readFileAt` reads the whole blob before checking `maxBytes` (additions, spec, standards). A `cat-file -s` check first would avoid holding a large planted blob in memory.
- **Duplicate items on retry.** An exception after the items are filed and before the transcript commit leaves the run interrupted. A resumed run that then succeeds files the items again.
- **Report folder ownership (Linux).** The container runs as uid 1000, and the folder is owner-only on the host. If the host user isn't uid 1000, the reviewer can't write, or the engine can't remove what it wrote. This is functional, not a security gap; check it in the real-Docker acceptance run.
- **GitHub autolinks.** `plain()` escapes `:` and `.`, so `https://` and `www.` autolinks can't form. Emails (`a@b\.com`) weren't checked against a GFM renderer. The F-001 extension uses markdown-it with `html: false` and `linkify: false`, and HTML-escapes front matter labels, so the inbox is fine.
- **Free-text answers as SR text.** FR-9 copies the owner's answer word for word into section 9 (F-005 SR-11's rule). M1 is about what the engine accepts as an answer, not this rule.

## Checked and fine

- **Tool and network narrowing (SR-1, AC-3).** `reviewerPolicy` refuses a project role with any tool outside `Read, Grep, Glob, Write, Skill`, any command or any network host. The write rule becomes exactly the run's report path, with the project's denies kept (SR-12). The proxy grant is the role's empty network list, so the gateway only. The factory MCP server has no tools. Every file tool goes through the PreToolUse gate and `canUseTool` (the F-007 H1 fix), and paths outside the worktree are refused, so `/proc` and the mounts aren't readable.
- **Read-only worktree and report mount (SR-12, FR-2).** The worktree is mounted read-only for a role whose only write is under `.factory/`. The report mount is refused for a writing role, or outside `/workspace/.factory/`. The end-of-session check runs with an empty write allow list, so any worktree change is a breach. The report folder is engine-owned, keyed by run id, removed before the run and in `finally`. The session volume is per run and removed at the end. Nothing the reviewer writes persists into another run. An orphaned container from a crashed engine would write into the deleted folder's inode, not the new one.
- **Report file read (SR-8, AC-13). Reproduced.** The name is engine-fixed (no slash), in an engine-made folder, read only after `stopAgent`. `lstat` then `open(O_NOFOLLOW | O_NONBLOCK)` then `fstat`, with the size checked twice. Links, folders and FIFOs are refused. A 131,000-deep nested array is refused by the depth check (V8 parses it iteratively). Wide arrays are L1.
- **Worktree population.** `populateWorktree` now refuses links and colliding names (F-007 H2 fixed), so the engine's `mkdirSync` for the mount point and the rendering write can't follow a link.
- **Validation (FR-5).** Envelope, role, feature, stage and commit; known criteria from the standards actually given; known severities; every checklist question answered; caps; control and bidi characters refused; unknown fields refused; option ids fixed to A to D. Errors name fields only, so no reviewer text goes back to it or into the log.
- **Rendering and inbox (SR-4, AC-14).** Every reviewer string goes through `plain()` (Markdown and HTML control characters escaped, line breaks flattened). Front matter is built by `YAML.stringify` from engine values, plus option labels as quoted strings, which the extension HTML-escapes. Titles are engine text.
- **Analyst input (SR-4, SR-9).** The findings are JSON strings in a labelled block after the engine's instruction. The whole first turn is scanned before the session starts, and a hit stops the run with an engine-text Security item.
- **Additions (SR-10).** Read from the config repo's `main` commit through `readFileAt` (regular file, no link, 64 KiB). The path passes `checkRepoPath`. Given as a JSON string after the factory standards. A refused file runs the gate on factory standards with a Security item (narrowness is L2).
- **Standards (FR-3).** Read from the master commit `factory.version` names, never a working tree. Criteria, checklist and severities come from that file only.
- **Stage control (SR-5).** Only `acceptGate1` (no findings, after SR-7) and `resolveGate1` (FR-9 passed) write `readiness_gate`. `interview_spec_ready` only ever writes `security_gate_1`. Transcript entries are hash-chained, and a broken chain stops every Gate 1 path. One job per feature (`jobs`) keeps the analyst and the reviewer apart.
- **Run cap and restarts (SR-11, FR-1, FR-10).** The fourth run files a Security item and blocks. A feature that returns with pending findings gets the FR-9 check, not a run. A blocked feature starts nothing. Interrupted runs resume through the run book, up to `MAX_RESUMES`. Cost looseness is L3.
- **Config (FR-11, AC-10).** The new sections and the model are optional, so an old factory version runs no Gate 1. A project's `limits:` can only lower them (a section the master lacks is ignored, not added). The values match H-0095.
- **Billing check and caps (SR-6).** `billingMismatch` runs before each session, and the caps come from `security_reviewer`.
- **S4.** No new library; `npm audit` clean.
