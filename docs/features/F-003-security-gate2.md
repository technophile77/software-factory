## Checked and fine

- **SR-3:** the secret loop records only the path, line and rule name. Inbox items say "The value is not copied here." AC-4 and the randomized test confirm the key appears in neither the JSON, the Markdown nor the item (re-run and passing). The exceptions are #13 and the agent-side path in #8.
- **SR-4:** `Repo.path` resolves with `realpath` and checks the result against `root + os.sep`. Symlinks are never read. Links pointing outside the repo are reported (tested). Links inside are skipped. The `os.walk` fallback uses `followlinks=False`, and FIFOs and other non-regular files are excluded by `isfile`.
- **SR-6 (checker):** the checker runs a single `subprocess.run(["git", "-C", <realpath>, …])` with fixed arguments and a timeout, and has no `shell=True`, `os.system` or `eval`. The root is absolute, so it can't be read as an option.
- **SR-8 (factory YAML):** `parse_yaml` rejects anchors, aliases, tags, multi-document files, tabs and duplicate keys with `YamlError`. The property test (200 cases) shows it fails only that way, except for #16. An unreadable workflow is a gap (tested).
- **Isolation:** `CHECK` runs Python with `-I`, so a planted `json.py` in the repo or the current directory is not imported. Only the standard library is used, so S4.1 and S4.4 are not triggered.
- **Item rendering:** frontmatter strings are JSON-quoted, so a file path containing newlines or `---` can't inject frontmatter fields. Markdown table cells escape `|` and newlines.
- **Manifest validation:** `_inside` rejects absolute paths, drive paths and `..` segments. Protected defaults and the maturity ceiling are enforced (tested, AC-11).
- **CI template (SR-5):** it has top-level `permissions: contents: read`, a `pull_request` trigger (not `pull_request_target`), no `secrets.` references (tested), every `uses:` takes a SHA placeholder, and installs come from the lock file (`npm ci`, `--require-hashes`, `--locked`).
- **Token scopes:** they cover this repo only and leave out Administration and Workflows, as ADR 0006 asks. FR-10 is met: the skill neither creates nor stores the token.
- **S2:** not applicable (no endpoints).
