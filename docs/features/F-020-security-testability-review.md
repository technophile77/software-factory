# F-020 Security and Testability Review (requirements review)

- **Feature:** F-020 The rest of the agents' data moves to JSON, with schemas, spec v1
- **Reviewer role:** security-reviewer, against `docs/security-standards.md`
- **Date:** 2026-11-14
- **Maturity level:** Rapid prototype (the factory repo's level). Only
  Critical findings block there (`security-blocking.json`).
- **Result:** 9 findings: 0 Critical, 0 High, 5 Medium, 4 Low. Nothing
  blocks. The owner's decisions (ADR 0032, H-0240, proposal 0034 decision
  2: hand-edited config stays YAML) are not re-opened, and OQ-1 is not
  decided here. Recommendations are proposed as SR-4 to SR-12 in the spec,
  for the owner to approve.

**Already covered by the spec or decisions:** the engine validates every
agent result and record (SR-1, FR-3), and a newer or unknown schema version
is refused, not guessed (section 6). Advisor and web reader strings are
rendered only as escaped plain text and never used as commands, paths or
URLs (SR-3). The web reader's sources are only pages the engine fetched
(FR-7, AC-8). String limits match today's (SR-2). A session without a valid
result is a failed run, not a retry loop (FR-9, AC-11). FR-10 tightens the
role policy, so it is not a widening under S8.5. No new runtime dependency:
zod 4.6.7 and Agent SDK 0.3.311 are already pinned and reviewed (section 5).
The schema files under `docs/schemas/` and their CI check come in through
H-0244, so they are change-controlled (S6.3).

**Not applicable:** no new external service or permission for any agent.
The advisor and web reader already exist; only their output format
changes, so there is no new S9.7 threat model. The only new outside
service is the schema fetch in OQ-1 (a), which runs in the owner's editor,
not in an agent (finding 9). No new secrets or sensitive data (S3.1,
S3.2).
